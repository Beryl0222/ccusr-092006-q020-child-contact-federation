# 儿童联系人跨品牌互通服务

不同品牌的儿童手表之间要能加为班级联系人，但互通**不等于**开放陌生人搜索，
也**不等于**把孩子的社交关系交给平台做广告画像。本仓库是一条"更窄的通路"的
参考实现与领域约定：监护人先建立真实关系，学校证明或面对面短码只负责**一次相识**，
之后经过加友请求、孩子本人确认、对方监护人同意才成关系；文字、语音、群组、位置
按年龄段分别开放；跨品牌交换的只有完成当前动作所需的最少标识。

资料全部为虚构领域约定，不含真实个人信息、生产连接或外部账号。

## 这条通路窄在哪里

1. **没有陌生人搜索接口**：服务表面不存在按姓名/学校/通讯录查找儿童的方法
   （测试会断言 `searchChildren` / `listChildren` 不存在）。跨品牌加友的唯一
   入口是一次性"相识凭证"：
   - 学校证明 `SCHOOL`：有效期 **7 天**，只携带班级范围码，不带花名册；
   - 面对面短码 `FACE_TO_FACE`：有效期 **10 分钟**。
   凭证兑换一次即焚，重复兑换返回 `INTRO_REDEEMED`。
2. **跨品牌只见假名**：每个儿童对每个品牌呈现不同的关系假名（`deriveHandle`，
   联盟盐派生），对端看不到稳定儿童 ID；账号迁移时轮换盐，旧假名在 14 天
   窗口后不可链接。
3. **投影最小化**：加友请求只含 `{一次性凭证, 发起品牌, 接收品牌, 关系假名, 年龄段}`，
   没有姓名、生日、学校、头像、通讯录、电话；路由投影只含投递所需字段。
4. **位置是独立同意项**：加友永不默认带位置；位置只能由监护人逐次开启
   **限时会话**（默认 1 小时，到时自动结束），不存在"常开授权"。
5. **证据与业务流分离**：安全投诉的事实进入独立证据库（只追加、加密静态存储、
   读取必须登记、保留 365 天），业务接口与申诉信封只能拿到引用哈希。

## 加友主流程与期限

```
GUARDIAN_LINKED（本方已验证监护人，互通的根）
   └─ issueIntro  学校证明 7 天 / 面对面短码 10 分钟（一次性）
        └─ redeemIntro        加友请求，7 天不处理自动失效
             └─ confirmByChild        孩子本人确认（双向确认的第二向）
                  └─ grantConsent     对方监护人同意，确认后 7 天内未同意则回退
                       └─ 关系 ACTIVE，按年龄就低开放能力
```

| 等待状态 | 期限 | 到期结果 |
| --- | --- | --- |
| 学校证明 | 7 天 | 不可兑换（`INTRO_EXPIRED`） |
| 面对面短码 | 10 分钟 | 不可兑换 |
| 加友请求 | 7 天 | 自动失效，可重新发起 |
| 监护同意（自孩子确认起） | 7 天 | 请求回退失效 |
| 设备换绑确认 | 3 天 | 自动取消，关系不变 |
| 位置会话 | 默认 1 小时 | 自动结束 |
| 撤销后只读缓存 | **24 小时** | 标识清除，只剩无含义墓碑 |
| 监护权变更宽限 | 30 天 | 未被新监护人复核的老关系自动撤销 |
| 账号迁移旧手柄 | 14 天 | 旧假名不可链接 |
| 品牌退出挂起 | 90 天 | 未随迁移转走的关系自动撤销 |
| 紧急联系人复核 | 90 天 | 能力暂停，复核后恢复 |
| 投诉证据保留 | 365 天 | 到期清除 |

撤销是**立即生效**的：消息与位置从撤销一刻起不再投递；24 小时是给各方
只读缓存的失效宽限，不是联系还能继续使用的窗口。

## 年龄—能力矩阵（双方就低不就高）

| 年龄段 | 文字 | 语音 | 群组 | 位置 |
 | --- | --- | --- | --- | --- |
| <8 | ✅ | – | – | – |
| 8–11 | ✅ | ✅ | 仅可被邀请进班级群 | – |
| 12–15 | ✅ | ✅ | ✅ | – |
| 16+ | ✅ | ✅ | ✅ | 仅独立同意 + 限时会话 |

矩阵是上限，监护人可以逐条收窄（`setCapability`），不能突破上限。
**紧急联系人例外**：监护人预设的真实紧急关系（如家长、老师）绕过年龄矩阵，
低龄儿童也能在紧急关系中用语音并由监护人开限时位置会话；但每童最多 3 个、
每 90 天必须复核一次，逾期能力暂停。

## 幂等：离线手表重发不制造重复关系

所有写命令接受 `commandId`（客户端命令号）。同一 `commandId` 重放时服务端
直接返回首次结果并记录 `COMMAND_DEDUPLICATED`，不产生第二个请求、第二条关系
或第二次能力变更。配对索引（两个儿童的有序键）额外保证同一对儿童不会并存两条关系。

## 四条连续处理路径

- **监护权改变** `changeGuardianship`：老联系人不立刻断裂，进入 30 天只读宽限；
  期间不能扩张能力、不能发起新联系；新监护人对每条老关系表态
  （`reviewUnderNewGuardian` 保留=重新同意 / 拒绝=立即撤销）；逾期未复核自动撤销。
- **账号迁移** `migrateAccount`：立即换发新关系假名，14 天内旧假名仍可路由
  （`resolveHandle` 返回 `PREVIOUS_GRACE`），窗口后不可链接；可跨品牌迁移。
- **品牌退出联盟** `brandExit`：即时暂停新联系与投递；给用户 90 天迁移豁免，
  账号迁到存续品牌后 `restoreAfterMigration` 恢复关系；90 天后仍挂起的关系自动撤销。
- **紧急联系人例外** `declareEmergencyContact` / `reviewEmergencyContact`：
  唯一不需要一次相识的入口，监护人预设、3 个上限、90 天复核。

以上撤销动作都走同一条撤销路径：立即切断 + 24 小时缓存承诺。

## 可解释性与跨品牌申诉

- `authorize(relId, capability, actorId)` 是投递前闸门；`explain(...)` 用同一套
  判定生成家长能读懂的卡片：原因码 + 中文说明 + 到期时刻 + 下一步，对方仅显示
  `品牌:假名首末位`，不出现对方真实 ID 或档案。原因文案见 `REASON_TEXT`。
- `fileAppeal(...)` 生成跨品牌申诉信封（schema `ccf-appeal/1`）：只含**本条**
  关系引用与证据库引用，`other_children_profiles` 结构性恒为空数组；
  被申诉品牌通过 `appealsFor(brand)` 只看到信封，看不到其他儿童资料。

## 代码结构

| 文件 | 内容 |
| --- | --- |
| `src/child_contact_federation.js` | 事件种类、原因码与家长可读文案、事件校验 |
| `src/policy.js` | 全部期限与年龄—能力矩阵（单一事实来源） |
| `src/identifiers.js` | 关系假名、最小投影、解释卡片与申诉信封 |

| `src/federation.js` | `FederationService`：状态机、幂等、期限清扫（`sweep`）、连续路径 |
| `data/sample.json` | 用于核对格式的虚构事件 |
| `tests/` | 领域契约与 29 个端到端流程测试 |
